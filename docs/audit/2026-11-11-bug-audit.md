## Pola lintas modul (akar masalah yang berulang)

1. **Teardown sesi tidak seragam** (CORE-02, CORE-04, AUTH-02, AUTH-06, PROF-04, PROF-10).
   - Ada lima jalur yang mengakhiri sesi: logout, 401, koneksi putus, token kedaluwarsa saat splash, dan reinstall iOS.
   - Masing-masing membersihkan hal yang berbeda: token FCM, sign-out Google/Firebase, Keychain.
2. **Idempotency-Key tidak dipegang per niat pengguna** (PRMT-01, PRMT-07, PRMT-08, PROF-08, AI-02, INBOX-01, GAMS laten).
   - Sebagian request membuat key baru setiap tap.
   - Sebagian lain menahan key walaupun isi form sudah berubah.
3. **Kegagalan ditampilkan sebagai "kosong"** (PRMT-14, HOME-15, ATTP-12, ATTD-04, ATTP-08).
   - Error ditelan lalu dikembalikan sebagai `[]` atau `null`.
   - Akibatnya UI menulis "Belum ada …" atau "Absensi sudah lengkap".
4. **Race refresh vs load-more tanpa token generasi** (PRMT-15, HOME-16, ATTP-03, ATTP-10). Gejalanya baris ganda, halaman hilang, atau filter tercampur.
5. **Jam perangkat vs jam workspace** (PRMT-12, HOME-04, HOME-09, HOME-10, HOME-12, ATTP-16, ATTP-20). `WorkspaceClock` sudah ada tetapi tidak dipakai konsisten.
6. **Angka desimal-string diparse dengan `asInt`** (PROF-03, HOME-08). `"5000000.00"` menjadi `null`.
7. **`Get.back()` hanya menutup snackbar** (GAMS-04, dialog tolak di Inbox). GetX 4.7.2 menutup snackbar dulu kalau ada yang terbuka.
8. **Rute/UI yang diiklankan tapi tidak ada** (GAMS-01, ITMS-01, CORE-06, HOME-06, HOME-14).

## CRITICAL

### CORE-01 ✅ — Push notification mati total di semua Android
- **Lokasi:** `lib/utils/notification/notification_services.dart:30`, `lib/bootstrap.dart:123-141`
- **Masalah:** commit `66a5c83` menghapus semua `mipmap-*/ic_launcher.png`. Yang tersisa hanya `launcher_icon`.
  - `AndroidInitializationSettings('@mipmap/ic_launcher')` jadi merujuk resource yang tidak ada.
  - flutter_local_notifications 19.3.1 memvalidasi ikon dan melempar `PlatformException(invalid_icon)`.
  - Langkah boot `notifications` gagal, `hasNotifications=false`, sehingga `registerMessaging()` dilewati.
- **Akibat di semua handset Android:**
  - Channel tidak dibuat.
  - Listener FCM (foreground, background, tap) tidak terpasang.
  - Token tidak dikirim ke `/push-tokens`.
  - Izin POST_NOTIFICATIONS (Android 13+) tidak pernah diminta.
  - Kegagalan ini senyap, karena `AppLogger.warning` no-op di release (CORE-07) dan `BootReport` diabaikan `main()`.
- **Bukti:** `find android/app/src/main/res -name "ic_launcher*"` hanya menemukan `drawable-*/ic_launcher_foreground.png`. Tidak ada `mipmap/ic_launcher`.
- **Saran:** pakai resource yang ada (`@mipmap/launcher_icon`, atau lebih baik ikon notifikasi monokrom di `drawable`). Buat kegagalan boot terlihat di release.

### CORE-02 ✅ — iOS: reinstall langsung login sebagai pengguna sebelumnya
- **Lokasi:** `lib/core/storage/secure_store.dart:33-41`, `lib/core/storage/token_storage.dart:44-48`
- **Masalah:** item Keychain iOS bertahan setelah app di-uninstall. Tidak ada penanda first-run di GetStorage untuk membersihkan secure store (grep `deleteAll`/`first_run` kosong).
- **Skenario:** karyawan A uninstall tanpa logout, lalu iPhone kantor diserahkan ke B. B install ulang, lalu `restore()` membaca token A. `/auth/me` sukses, dan B melihat Beranda, slip gaji, serta data pribadi A.
- **Saran:** saat bootstrap, bila flag instalasi di GetStorage belum ada, hapus kunci token/tenant di secure store, lalu tulis flag tersebut.

### PROF-01 — Seluruh rekam `/profile` (gaji, rekening, NIK, keluarga) tersimpan plaintext di GetStorage
- **Lokasi:** `lib/features/profile/data/repositories/profile_repository.dart:64-69`, ditulis lewat `lib/features/auth/data/repositories/session_repository.dart:129`
- **Masalah:**
  - `_fetch` menggabungkan **seluruh** body `/profile` ke `AuthUser.raw`, lalu `updateUser` menulisnya ke `auth_user_json`. File itu JSON plaintext di direktori Documents.
  - Isinya termasuk `salary.basic_salary`, `employee.bank_*`, `addresses[].identity_numbers` (NIK), `families`, dan `detail`.
  - Manifest tidak memasang `allowBackup="false"`, jadi data ikut backup Google Drive. Di iOS ikut backup iCloud.
  - Project ini sudah memindahkan token keluar dari file yang sama karena alasan yang persis sama (ADR-0005).
- **Bukti:**
  ```dart
  await _session.updateUser(
    AuthUser.fromJson({...?_session.user?.raw, ...identity, ...body}),
  );
  ```
- **Saran:** ke sesi, gabungkan hanya field identitas (nama, avatar, status). Data payroll/PII tetap di memori atau secure storage. `payroll_test.dart` saat ini malah mengunci perilaku merge ini.

## HIGH

### CORE-03 ✅ — `device_id` Android = `Build.ID` (label firmware), bukan ID perangkat
- **Lokasi:** `lib/core/services/device_info_service.dart:41-43` (dipakai di `login_controller.dart:92,120`)
- **Masalah:**
  - `AndroidDeviceInfo.id` adalah `Build.ID` (mis. `TP1A.220624.014`). Nilainya sama untuk semua HP dengan model dan firmware yang sama, dan berubah setiap kali OS di-update.
  - Backend mengikat `users.device_id` ke nilai pertama dan menamai token Sanctum dengan nilai itu.
  - Fallback `'device_info_error'` dipakai bersama oleh semua perangkat.
- **Skenario:**
  - (a) Rekan dengan HP model yang sama bisa login sebagai A dan lolos sebagai "registered device", sehingga bisa titip absen.
  - (b) A update OS, lalu `can_record_attendance=false` sampai HR mereset.
  - (c) Login di HP kedua bertipe sama menghapus token HP pertama.
- **Saran:** UUID per-instalasi yang disimpan di secure storage (atau ANDROID_ID), plus rencana migrasi binding di server.

### CORE-04 ✅ — Setiap timeout atau gangguan jaringan pada request terautentikasi memaksa logout
- **Lokasi:** `lib/core/network/api_client.dart:421-444`, `api_exception.dart:60-66`, `lib/app/bindings/initial_binding.dart:116-125`
- **Masalah:**
  - `_guardSession` memanggil `onConnectionLost`, lalu `disconnectSession()` (sesi dihapus) dan `offAllNamed(login)`. Ini berlaku untuk **semua** request dengan `timeout`, `network_unreachable`, atau `transport_failure`, termasuk request latar.
  - Perilaku ini disengaja (`login_connection_lost_test`, `api_client_session_test`), tetapi pemicunya terlalu luas.
- **Skenario:**
  - (a) App resume dari doze, lalu `NotificationSyncService.refresh()` gagal karena radio belum siap. User logout tanpa melakukan apa pun (laporan awalnya NOTIF-01).
  - (b) `POST /push-tokens` latar timeout 30 detik, dan user terlempar dari Beranda.
  - (c) Submit wajah atau lampiran izin 5 MB di uplink lambat timeout padahal server sudah mencatat. User logout dan tidak bisa "cek dulu". Jalur `RefusalKind.unanswered` jadi tidak pernah terlihat.
  - (d) AI chat dengan jawaban di atas 30 detik (lihat AI-02).
- **Saran:** batasi pemicu ke request yang ditandai kritis, atau ke kegagalan berulang. Jangan perlakukan `timeout` sebagai koneksi hilang.

### AUTH-02 — Sesi berakhir di luar logout tidak melepas token FCM dan tidak sign-out Google/Firebase
- **Lokasi:** `lib/features/auth/data/repositories/auth_repository.dart:184-187` (restore expired), `:246-249` (`expireSession`), `:253-262` (`disconnectSession`), `:230-238` (logout gagal)

- **Saran:** satukan teardown sesi: hapus token FCM lokal (`deleteToken`) dan `signOut` identitas di semua jalur.

## Masalah laten (belum terjangkau UI, akan jadi bug begitu di-wire)

- **GAMS:**
  - Hanya `createServiceRequest` dan `createSpaceReservation` yang membawa Idempotency-Key. Create kendaraan, tamu, gate pass, parkir, ATK, insiden, dan `completeWorkOrder` tidak.
  - Tidak ada endpoint pengambil `inventory-locations`, padahal `createInventoryRequest` butuh `locationId`.
- **Profile:**
  - `submitTravelRequest` mengirim `departure_date`/`return_date`/`estimated_cost`, sedangkan model membaca `departs_on`/`returns_on`/`allowance_amount`.
  - `ExpenseClaim` dan `TravelRequest` memakai cast mentah `as String?`, dan daftarnya tanpa paginasi.
- **Kode mati:** expense claims, travel requests, performance plans, company policies, skills, devices/forget, ITMS my-assets/acknowledge, form tiket ITMS, dan `ActivityView` (`/home/activity`). Semuanya tanpa pintu masuk UI.

## Yang dicek dan dinyatakan aman

- **Firestore:** `recordSignIn` cocok dengan `firestore.rules` (7 key, `createdAt` hanya saat create, `serverTimestamp`, regex `lastTenant`).
- **Google sign-in 7.x:** `initialize()` di-memo sebelum `authenticate()`, dan pembatalan ditangani.
- **Splash:** guard navigasi ganda ada.
- **Kebocoran data saat logout:** guard 401 untuk akun lama di `_guardSession` ada. Cache Home dan Profil tidak bocor lintas akun.
- **Idempotency di ApiClient:** tidak ada retry otomatis. Key attendance stabil antar retry.
- **FCM:** background handler top-level dengan `@pragma('vm:entry-point')`, dan listener dipasang sekali.
- **TLS:** bypass **tidak** aktif di release.
- **Robustness parsing/UI:** sparkline, day strip, dan skeleton aman pada data kosong. Parsing model GAMS, ITMS, Inbox, dan Notifikasi null-safe.

## Keterbatasan

- Tidak ada yang dijalankan di perangkat. Lifecycle kamera/izin, liveness, dan Dynamic Type disimpulkan dari kode app, GetX 4.7.2, dan source plugin.
- Kontrak backend dicek terhadap `tenancy-app` lokal, yang bisa berbeda dengan produksi. Temuan yang bergantung padanya: AI-01, AI-03, AUTH-01, AUTH-04, AUTH-05, PRMT-01..05, PRMT-07/08, INBOX-02.
- Confidence Medium (tergantung bentuk data backend atau kebijakan bisnis): PROF-03, PRMT-06, HOME-05, HOME-06, HOME-08, HOME-09, UI-02, dan beberapa Low.
